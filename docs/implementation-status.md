## 与最初方案的收敛

- 管理数据集中到一个有界 `management.json`，包含管理员、机器人、仓库说明/可见性和持久化主秘密。所有管理修改通过一次原子替换提交，避免这些管理字段之间的跨文件提交问题；不将镜像清单或层元信息集中到此文件。
- `management.json` 含 `schemaVersion` 与全局修订，仓库另有修订用于页面冲突检查。管理 JSON 上限 8 MiB、机器人上限 1024，不定位为大规模企业平台。
- 协议令牌由自定义 Distribution AccessController 校验，使用短期 HS256 JWT；从主秘密派生独立的协议签名与上传状态签名材料，不依赖外部令牌服务。签名密钥轮换界面暂未提供；issuer 固定为 light，不与访问域名绑定。
- Registry 在程序启动时创建一次，不支持在进程内反复重建内核。所选版本的事件广播器由进程生命周期管理，退出时由操作系统回收；关闭接口负责取消内核上下文，不宣称该上游接口提供完整的可重复销毁语义。
- 仓库索引在成功写入清单与删除后失效，读取时刷新，并有 30 秒有效期；控制台支持显式重建。启动始终重新扫描事实数据，不直接信任磁盘缓存；未添加后台全库扫描任务。
- 首页镜像文件占用按已提交 blob 的逻辑大小统计，通过 Distribution 枚举/描述符 API 计数，排除管理元数据、缓存清单快照、链接与未完成上传；共享内容在各独立存储内按摘要去重。页面区分内容大小与文件系统实际卷容量，不显示未经准确计算的可回收空间。
- 机器人最近使用时间记录最近凭据交换，并按分钟合并持久化，不等同于每个镜像请求的精确访问统计。
- 首版不提供在线备份、单标签解绑、标签保留策略或公开仓库以外的匿名管理能力。
- 所选内核没有原生 Referrers API；subject 的删除保护由适配层补充，GC 保留全部存续清单。原始 subject/制品存储测试不代表完整 OCI 1.1 兼容。
- 删除 API 接收仓库名称与 tag，不再接受 digest 删除入口。删除多架构标签时可递归回收仅由该索引持有的无标签子清单；保留其它标签、索引或制品仍引用的子清单。

## Docker 环境下的维护流程调整

存储维护已从离线命令说明改为控制台直接发起的预览、确认执行与任务记录。应用在同一进程内暂停镜像请求准入、等待在途请求结束并独占存储，结束后恢复；维护页、会话与健康检查保持可用，无需 Docker socket、特权容器或第二个服务。

官方 GC/上传清理的删除调用在预览时被只读驱动适配器截获，记录候选数与逻辑文件体积；执行前重新校验候选指纹，并限制真实驱动只能删除已核对的目标。上传清理补充最近文件活动检查，避免清理近期恢复的旧上传。关闭 blob 描述符缓存，防止回收后 HEAD 返回过期结果。

任务状态写入 `jobs/maintenance.json`，最多 12 条，完整预览只保留每种类型的最近有效结果；在线预览超过 2 MiB 时提示使用离线入口。预览 30 分钟过期且仅可执行一次。停止实例会取消任务，重启会将遗留的排队/运行任务标记中断，不自动重试删除。

回归测试覆盖：预览不删除、范围变化拒绝执行、共享层保留、回收后 GET/HEAD 一致、请求排空和 503 提示、控制台/健康检查可用、旧上传近期活动保护、任务持久化与过期、中断恢复、驱动异常及记录写入失败。前端测试覆盖预览后确认、运行中禁止重复操作、闲置阈值和中断记录展示。
